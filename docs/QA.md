# 검증 결과

검증일: 2026-10-14 (Asia/Seoul)

## 통과

- Node 정적 빌드: 메인 1개, 프로젝트 상세 4개, 404 페이지 1개 생성.
- 사용자 사이트 `/`와 프로젝트 사이트 `/portfolio/`에서 각각 150개 내부 URL·이미지·CSS·JS·앵커 검증.
- 두 경로 각각 1440 / 768 / 390 / 320px에서 메인·프로젝트 5페이지 검증: 총 40개 페이지·화면 조합.
- 4개 상세 URL 직접 접근 및 새로고침 HTTP 200.
- 가로 넘침 없음, 이미지 로딩 성공, 페이지 JavaScript 오류 없음.
- 프로젝트 카드 → 상세 → 목록 이동, 상세 목차 앵커 이동.
- 원고 이미지 확대, Escape 닫기, 원래 링크로 키보드 포커스 복귀.
- 없는 URL은 404 응답과 홈 복귀 화면.
- JavaScript를 끈 상태에서도 FILLY 본문과 이미지 원본 링크 유지.
- 데스크톱·모바일 스크린샷을 렌더링하고 메인 및 상세의 타이포그래피, 줄바꿈, 이미지 배치 확인.
- 모바일에서 중복 경험 요약 패널을 생략해 소개와 운영 지표를 연속 배치.
- Q1·가이드·대화·TODO·임시 텍스트 제거 여부 자동 검사. OPIc 예정 점수 미표시.

최종 산출물은 사용자 사이트 `/` 설정으로 복원했습니다.

## 검증 환경과 한계

- macOS Chrome headless + Playwright, 별도 임시 브라우저 프로필을 사용했습니다.
- 화면 크기 검증은 브라우저 뷰포트 기준이며 실제 iOS Safari·Android 기기 테스트는 수행하지 않았습니다.
- GitHub Actions 배포 워크플로는 구성만 완료했습니다. 저장소 생성·원격 업로드·공개 배포 및 실제 Pages 도메인 접속은 수행하지 않았습니다.
- GitHub 저장소 `JAEMO-LIM/JAEMO-LIM.github.io` 조회는 404였습니다. 사용자가 선택한 신규 사용자 사이트의 저장소 이름을 공식 안내에 따라 `jaemo-lim.github.io`로 표기했습니다.
- GitHub Actions 공식 문서를 확인하여 checkout v6, setup-node v7, configure-pages v5, upload-pages-artifact v4, deploy-pages v4를 사용했습니다. Pages는 별도 설정 후 수동 워크플로로 배포합니다.
- 외부 저장소·영상 링크 전체의 공개 접근 권한이나 영상 내용은 검증 범위에 포함하지 않았습니다.
- 운영 지표는 사용자 제공 원고를 근거로 편집했으며 분석 시스템에서 독립적으로 재측정하지 않았습니다.
